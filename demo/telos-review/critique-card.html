Verdict for the panel
As built, the copilot wins back about 85 of the 120 seconds the business case counts on, almost all of it by writing the formal-Arabic reply. Four pilot fixes (start the draft early, lead with the answer, cut the reading, answer in one turn) close the gap. A pre-filled wrap-up takes it to about 3 minutes. The risk to watch is not speed. It is agents sending drafts they haven't checked.

What Serves the KRs
The copilot writes the formal-Arabic reply, which used to be the slowest part of the agent's job.
Mariam wrote in Franco-Arabic ("el felous hatrga3 emta?"). The draft comes back as a complete formal-Arabic reply in Arabic script, in the respectful plural, with an English gloss underneath. On a chat contact, writing a correct, formal, policy-safe Arabic reply is the biggest block of handle time, and the copilot removes it. This is where almost all of today's saving comes from: about 150 seconds in the budget above.

Every contact starts with a wait of about 16 seconds, and the agent has to trigger it.
The customer's message is already in the case on screen 02, but nothing happens until the agent clicks "Ask copilot". Screen 03 then shows only "Reading policies and this customer's records…" while the button spins. The metrics row on 04 records 15.75s for this draft. 9
Nothing shows whether the agent checked the draft, and the key result rewards not checking.
Send is live the moment the draft lands on screen 04. The fastest path is to read the Arabic and click Send without opening a single citation chip. The audit log compares drafted text with sent text, so a blind send and a carefully checked send look the same: both count as "accepted unedited". An agent judged on handle time has every reason to stop checking. Acceptance then climbs while live citation accuracy goes unmeasured. The eval set checks citations offline, but nothing does so on real traffic. In a bank, one confidently wrong reply about a customer's money costs more than the seconds saved on a hundred correct ones.

How did I get this?
On 04 the Send button is enabled with no precondition. The edit report (evals.edit_report) measures the share of each draft that agents changed, but there is no event for opening a source. This is a known pattern with assistive AI (automation bias): reliance grows as the tool is right more often, which is exactly when an error slips through. The copilot's high eval scores make this more likely, not less.
10
When the draft is wrong, the agent ends up slower than with no copilot, and this review only covers one of the three intents.
"Flag as wrong" logs a note, and then the agent starts from scratch. By then they have already spent the 16-second wait and the time reading the draft, and there is no way to say "fix this one thing" and get a corrected draft. A wrong draft costs about 90 seconds more than no copilot at all, so the minute budget depends on how rare wrong drafts stay. Separately, every screen here is a dispute-status chat. Fee explanations and card replacements are the other two-thirds of scope, and they have different failure modes (a fee waiver needs approval, a card order moves money) that this review hasn't seen.
